# 검증 기록 — 2026-11-02, v0.1.0

실제 고객 자료·실제 API 키는 사용하지 않았습니다. **실제 Claude 호출은 0회**입니다. API 부분은 네트워크를 호출하지 않는 가짜 응답으로 검증했습니다.

## 확인한 동작

- `npm test`: 12개 통과. ZIP 경로 탈출·암호화·링크·체크섬 손상·크기/개수 제한, 외부 Origin/Host 차단, 키 미노출, 전송 동의 필수, 원문 근거 불일치 처리, SDK 재시도 차단, 중단 구간 재개, 결과 XLSX의 실제 셀 값과 문자열 타입을 검증했습니다.
- `npm run check`: JavaScript 문법 검사 통과.
- `node scripts/verify-local-ocr.js`: 가상 한국어 영수증 PNG/JPG/WebP, 이미지 스캔 PDF, XLSX, HWPX, 그림을 넣은 DOCX를 실제 로컬 kordoc으로 읽었습니다. 영수증의 `2026-01-31`, `1,250,000원`, 한글 계약 자료의 `450,000,000원`을 확인했습니다. 문서별 소요 시간은 이 PC에서 약 0.4~2.3초였고 일반 자료 성능 보장은 아닙니다.
- Chrome에서 가상 ZIP을 직접 선택해 업로드했습니다. 5개 항목 중 지원되는 4개 파일을 읽고 HEIC 한 개는 미지원으로 남겼습니다.
- 사진 원본과 스캔 PDF가 화면에 표시되는 것을 확인했습니다. API 키 없이 분석 버튼을 누르면 키 설정 안내가 열리고 요청은 보내지 않았습니다.
- Chrome에서 내려받은 XLSX를 다시 열어 네 시트와 미지원 파일 행을 확인했습니다. 분석 전 내보내기에서는 핵심항목 시트가 빈 상태로 유지됩니다.
- 별도 가짜 응답 서버 `test/ui-server.js`에서 분석 결과 표시 → 근거 버튼 → 해당 추출 원문 강조를 확인했습니다. 이 서버는 provider를 호출하는 코드를 사용하지 않습니다. 실제 실행은 `src/main.js`를 사용합니다.
- 테스트 상태·생성 자료·화면 기록이 Git에서 제외되는 것을 확인했습니다. 실제 앱 저장소와 UI 테스트 데이터 폴더를 분리했습니다.
- 최종 일반 실행에서 v0.1.0, API 키 없음, OCR 준비 완료, 실제 작업 0개를 확인했습니다. 검증 서버는 종료했습니다.

실행 기록과 가상 자료는 무시되는 `test-artifacts/`에 있습니다. `local-ocr/report.json`, `tests.txt`, `ui-mock-result.jpg`, `ui-ocr-review.jpg`가 주요 근거입니다.

## 발견하고 고친 문제

- 외부 링크를 통해 첫 화면을 열 때도 cross-site 차단이 적용됐습니다. 첫 화면 접속은 허용하고 데이터 API에만 교차 출처 차단을 적용했습니다. Chrome 접속과 차단 회귀 검사를 모두 통과했습니다.
- ZIP 목록이 제한 때문에 중간에서 끊긴 뒤 개별 파일을 다시 읽으면 전체 목록 누락 경고가 지워질 수 있었습니다. 압축 목록 오류를 별도로 보존하고 추출된 파일을 읽은 뒤에도 계속 표시하도록 고쳤습니다.
- ZIP 크기 제한 테스트의 두 번째 시험 파일이 의도한 제한보다 한 바이트 컸습니다. 시험 데이터만 제한 안으로 고친 후 차단/허용 두 경계를 확인했습니다.
- 전체 페이지 스크린샷은 한 번 시간 초과가 났습니다. 현재 표시 영역 캡처로 재시도해 파일 저장을 확인했습니다.
- 초기 개발 때는 이 저장소에 Git 작성자 이름·이메일이 없어 커밋을 만들지 못했습니다. GitHub 업로드 요청 후 연결된 `simdorei` 계정과 기존 프로젝트의 작성자 설정을 대조하고, 확인된 GitHub noreply 주소를 이 저장소에만 적용했습니다.

## 다른 PC 설치 준비

- `setup.cmd`와 `scripts/verify-setup.js`를 추가했습니다. Node.js 버전 확인 → 고정된 의존성 설치 → 공개 OCR 모델 다운로드/검증 → 실행 모듈 확인을 수행합니다. 어느 단계든 실패하면 완료로 표시하지 않고 종료합니다.
- 기존 `node_modules`와 OCR 모델을 복사하지 않은 별도 임시 폴더에 스테이징된 소스만 가져와 `setup.cmd --no-pause`를 실행했습니다. 의존성과 모델을 새로 설치했고 종료 코드 0을 확인했습니다. OCR 의존성 네 개가 모두 새 설치 폴더에서 로드되는 것도 확인했습니다.
- 그 새 설치본에서 PNG/JPG/WebP·스캔 PDF·XLSX·HWPX·그림 포함 DOCX의 원문 값 인식을 다시 확인했습니다. `start.cmd`로 띄운 실제 서버에서도 v0.1.0, OCR 준비 완료, API 키 없음 상태를 확인하고 종료했습니다.
- 모델이 없는 별도 경로를 지정하면 설치 검증이 종료 코드 1로 실패하는 것을 확인했습니다. 이 실패는 의도한 누락 감지 시험입니다.
- 업로드할 Git 파일 목록, 긴 API 토큰/개인 키 패턴, 의존성 다운로드 URL을 확인했습니다. 원본·결과·화면·로그·OCR 모델·node_modules는 포함하지 않았고 다운로드 URL에 자격 증명이 없었습니다.
- `npm test` 12개와 JavaScript 문법 검사를 통과했습니다. 다른 물리 PC나 Windows ARM, macOS에서 실행한 검증은 아닙니다.

## OCR 검토 글줄 표시

- 점수 0.80 미만·점수 없음·본문 제외 글줄의 위치, 내용, 점수와 사유를 화면과 Excel에 표시합니다. 삽입 그림의 OCR 글줄도 저장하며, 기존 저장 결과는 남아 있는 원시 OCR 정보로 상세 목록을 구성합니다.
- 자동 검사 18개와 JavaScript 문법 검사 23개를 통과했습니다. 경계값 0.80, 낮은 점수, 높은 점수지만 제외된 줄, 점수 없음, 삽입 그림, 과거 결과 조회, Excel의 수식 문자열 안전성을 확인했습니다. 모든 줄이 제외된 파일은 검토 정보를 보존하고 빈 유료 분석 요청을 막습니다.
- 실제 로컬 OCR로 PNG/JPG/WebP, 스캔 PDF, XLSX, HWPX, 그림 포함 DOCX의 원문 값 보존을 확인했습니다. OCR을 사용한 형식에서는 글줄 정보가 남고 DOCX 삽입 그림 위치가 보존되는 것도 검사했습니다.
- Chrome에서 상세 보기 → PDF 원본 열기, 삽입 그림 이름, 모든 줄이 제외된 파일의 분석 선택 차단을 확인했습니다. 실제로 내려받은 Excel의 네 시트와 검토 글줄 5행을 읽어 확인했습니다. 화면 점수와 제외 상태는 표시 동작을 점검하기 위해 지정한 가상 값이며 OCR의 실제 정확도 평가가 아닙니다. Claude 호출은 없습니다.
- 기록은 무시되는 `test-artifacts/ocr-review-ui/`와 `test-artifacts/local-ocr/report.json`에 있습니다. 모델 점수 0.80은 검토를 안내하는 기준이며 정답 여부를 보장하지 않습니다.

## 남은 확인 및 제한

- 실제 Claude 계정의 키 인증, 이용 가능한 모델, 잔액·과금, 실제 API의 분석 품질은 **미검증**입니다. 화면에서 키를 입력한 뒤 사용자가 선택한 자료로 첫 분석을 해야 확인할 수 있습니다.
- 실제 양도세 자료, 오래된 HWP/XLS, PPTX, 손글씨·흐린 사진, 큰 ZIP·장시간 운용은 아직 대표 자료 검증을 하지 않았습니다. 지원 목록은 파싱 경로가 있다는 뜻이며 완전한 인식 보장이 아닙니다.
- 소스 인용 검사는 문자열 포함 여부를 검사합니다. 지급일/계약일 혼동처럼 의미 해석이 잘못될 수 있어 사람의 검토가 필요합니다.
- `npm audit --omit=dev`: 높은/치명적 경고 0, 중간 등급 영향 패키지 9개. ExcelJS의 전이 의존성에서 경로 탐색 glob/minimatch 및 일부 UUID 함수 관련 경고가 남습니다. 현재 출력은 `workbook.xlsx.writeBuffer()` → JSZip 경로이며 사용자 지정 glob 탐색, 스트리밍 폴더 압축, UUID v3/v5/v6는 사용하지 않습니다. 영향 패키지 경고를 없애기 위해 호환성 확인 없이 상위 버전을 강제하지 않았습니다. 공개 서버나 외부 배포로 확대하기 전에 의존성 교체/업데이트를 다시 평가해야 합니다. 원문 결과는 `test-artifacts/npm-audit.json`입니다.
